# 阶段：proposal — 选题提案

**产物**：`plan/proposal.md` · **需审批**（data-explainer、documentary；shorts 跳过）

一页纸，让用户在花任何渲染成本之前确认“讲什么、怎么讲”。

## 模板

```markdown
# 提案：<标题>

- **角度**：一句话说清这条视频的观点或悬念。
- **受众**：谁看、需要多少背景知识。
- **长度 / 画幅 / 风格**：约 N 秒 · 16:9 · midnight-data
- **结构**：钩子 → … → 收束（每段一行：观众此刻的问题 → 这段怎么回答 → 计划用的场景类型）
- **数据纪律**：数据来源构成、哪些数字只是媒体转述
- **不做什么**：明确排除的话题（防止脚本跑偏）
```

## 按观众的问题排结构

不按“我要讲哪些点”排，而按观众脑子里依次冒出来的问题排。每一段回答上一段留下的那个问题，回答完自然引出下一个：

| 观众此刻在想 | 这一段做什么 |
|---|---|
| 这是什么？跟我有什么关系？ | 钩子：反常识的数字或冲突，3 秒内抛出 |
| 真的假的？到底多大？ | 给证据：原始数字、对比、实拍 |
| 为什么会这样？ | 讲机制：拆成一两个原因 |
| 可是…不是…吗？ | 转折：回应最可能的质疑 |
| 所以呢？ | 收束：一句可以带走的结论 |

写完结构，把每一段的问题连起来读一遍：如果读起来像一段自然的追问，结构就成立；某一段答不出“观众此刻在问什么”，就删掉或并进别的段。这些问题会写进 script 的 `question` 字段。

## 原则

- 结构按 beat 走：`hook → setup → build → turn → climax → landing → credits`，不必每个都有，但 hook 和 landing 必须有。
- 前 3 秒必须给出问题或反常识数字。
- 长度先按 `targetSeconds` 定，脚本阶段用 budget 门控对齐（每秒约 4.8 个音节）。

审批：`onevideo approve proposal`。
